# 执行纪律（全员必读）

## 攻坚循环
- 先分类后动手：新功能（写测试→写实现）/修 bug（先写失败测试再修）/重构（测试全绿为起点，小步走）。
- 持续推进：中途禁止停下来等用户确认（技术歧义除外）；中间结论落盘到 `$TASK_DIR/notes.md` 防丢失。
- 单步预算：超长推导/设计拆步落盘，禁止脑内囤积多步结论。

## 三绿门禁（合并的唯一标准）
```bash
# Go 侧（全部零输出才算绿）
go build ./... && go vet ./... && go test ./... -race
# Python 侧
pytest -q && mypy . && ruff check .
```
任何一关不绿：就地修复，禁止"先合再说"。门禁失败的责任人跑门禁，禁止让别人替跑。

## 失败记录
每个失败方向记一行（原因 + 修复/绕过）到 `$TASK_DIR/failures.md`；同类错误第二次出现直接升级为评审红队军火项。

## 版式与落盘
- 任务目录约定：`./.tasks/<date>-<slug>/`（TASK.md、notes.md、failures.md、experiments/）。
- 长文档分段写入：>150 行的文件先骨架后逐节补全，单次写入 ≤150 行。
- 大代码同理：先可运行骨架，再逐功能补全，每步过编译。
